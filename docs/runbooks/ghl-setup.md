# Runbook: connect a firm's GoHighLevel sub-account

Phase 1. Takes about an hour per firm once the snapshot exists. Do it in staging first.

## 1. Sub-account

1. Create the firm's GHL sub-account (one per firm; never shared). Complete A2P 10DLC
   registration and number porting or forwarding (onboarding checklist, spec Section 13).
2. Load the LexDesk snapshot (`ghl/snapshot/manifest.md`). Turn off GHL's own appointment
   confirmations and reminders; A7 sends them.

## 2. API access

1. In the sub-account: Settings > Private Integrations > create a token for "LexDesk" with these
   scopes only: `contacts.readonly`, `opportunities.readonly`, `calendars.readonly`,
   `calendars/events.readonly`, `conversations/message.readonly`, `conversations/message.write`.
   **VERIFY** the scope names in the GHL UI.
2. Put the token in the firm's Render env group as `GHL_PRIVATE_TOKEN` and the sub-account id as
   `GHL_LOCATION_ID`. `GHL_WEBHOOK_SECRET` was generated by `pnpm provision-firm`
   (`.provision/<slug>/env`). Never set these on a demo deployment; the app refuses to start.
3. Redeploy the web service and the worker.

## 3. Webhooks

1. In LexDesk, Settings > GoHighLevel shows the webhook URL and header name.
2. Paste them into each snapshot workflow's Custom Webhook action with the secret as the header
   value (`ghl/snapshot/workflows.md`). Publish the workflows.
3. Optional: if the firm installs a private Marketplace app, set its webhook URL to the same
   endpoint; its signed events are verified with GHL's public key.

## 4. Firm settings and templates

1. Settings > Firm: phone, website, consult booking page, intake form link.
2. Settings > Message templates: review each template **with the attorney** and approve. Nothing
   sends until approved. Editing clears the approval.
3. Settings > Features: A1, A2, A7 and F1 are on by default; switch off any the firm does not want.

## 5. Acceptance check (staging, then production)

1. Call the firm's number from a test phone and let it ring out. Within a minute the phone gets
   the A1 text and Intake shows a missed-call lead. Settings > GoHighLevel shows the event Applied.
2. Submit the website form with SMS consent ticked: A2 email and text arrive; the lead shows
   Google/UTM source if you used a tagged URL.
3. Book a consult on the booking page: confirmation text arrives; the lead shows Consult booked
   with reminders scheduled. Cancel it: reminders are cancelled.
4. Reply STOP to a text: the contact shows Do not disturb and no further texts are sent.
5. Settings > GoHighLevel > Run reconciliation now: finishes with 0 failures.
6. Work through the VERIFY list in `docs/ghl/api-notes.md` and record results in `docs/phases.md`.

## Operations

- **Failed events** appear in Settings > GoHighLevel with a Retry button. The sweep retries
  automatically 4 times with backoff first. Logs: `webhook processing failed` (no payloads logged).
- **Message outcome unknown**: GHL may or may not have sent it. Check the contact's conversation
  in GHL before doing anything; LexDesk never resends these.
- **Signing key rotation** (Marketplace app only): set `GHL_WEBHOOK_PUBLIC_KEY` to the new PEM
  and redeploy.
- **Secret rotation**: generate a new `GHL_WEBHOOK_SECRET`, update every workflow's header, then
  the env group. Deliveries with the old secret in between get 401 (whether GHL retries them is
  not documented); the nightly reconciliation repairs contacts, opportunities and appointments.
